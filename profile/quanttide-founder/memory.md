# 记忆条目

## 一、章节编号规范

单层连续编号「章号_标题」为全局正文轴，跨场景到定稿共用，与流程目录编号正交；预留空号宁空勿移；无法定位的素材不编号、保留原名；同章多份素材都用该章号命名；归档时取消编号。

## 二、标题与简介

拟定标题时按风格分组给出备选批次，供人按编号挑选。文艺、双关意象风格不受欢迎，偏好长句直白带钩子的网感标题。发布平台对一句话简介有字数上限，且不应与标题重复，需换角度表达。

## 三、章节定稿模板

frontmatter（标题加简介）→ 正文 → 分隔线 → 作者有话说；作者有话说跟随章节文件，不单建目录。定稿文件名用单级编号「章号_标题」。

## 四、创作资料的组织

发文资料按发布表单的字段组织：标题、基本信息（类型、视角、进度、风格）、文案、标签、一句话简介、立意。目录按创作阶段分层：母题、场景、初稿、改稿、定稿。

## 五、静态站点下线

下线目的常是收掉线上运维负担，不是内容撤回；内容本就开源、无人访问时，不要建议转私有。下线动作：删部署工作流、停 CDN 域名、清对象存储；仓库可保留，但从主仓库移除子模块引用。

## 六、发布流程

版本发布分两步：先补回缺失的历史条目，再新增当前版本条目；可用脚本核对条目覆盖的提交范围。

## 七、记忆仓的分工

记忆仓以手册与日志为主；洞察与语境另有归属，不在此堆积。多仓迁移逐层提交：内容仓 → 子模块 → 主仓指针。

## 八、任务看板的设计约束

评审模式一次只展示一张；分类字段严格用仓库文件夹名；标注与多行理由分两行；不设「选定做」「复制清单」按钮；保存即快照进历史、原子写盘、自动跳下一张，空标注不产生记录；随键入实时写盘。纯逻辑与界面类分离，便于无显示环境跑测试。

## 九、标签可达性（教训）

批量发布时，版本标签可能指向分叉自主干的孤立提交，主干缺该版本条目。纪律：CHANGELOG 提交必须先落在主干再打标签。标签存在不等于在 HEAD 历史中，用 `git merge-base --is-ancestor <tag> HEAD` 验证可达性。

## 十、跨作品共享素材层

共享素材层的组织几经变更：创作谈、创作日志、创作设定迁至记忆集；草稿箱与实验室目录删除，跨系列素材改放「观察站」（情绪日记作母题来源、社会观察另立）；流程目录为灵感、场景、初稿、改稿、定稿。

## 十一、分支图渲染（取舍）

分支可级联可汇聚、结局可带概率、史实线只是 DAG 中已走过的路径。首版深度分层横向带方案被否（「和要的 DAG 不够搭，还是比较线性」），改用 Sugiyama 从左到右布局：x 为时间与层级、y 为分支通道，fork 子树分独立纵向通道。生成前校验重复 id 与无环。正式方案定为桌面 GUI，浏览器版只是原型。
